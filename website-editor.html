CASE 02 · 个人网站实战

AI 做我的个人网站编辑

我说出想法，AI 把它变成网页。
哪里不满意，就指出来，一起改到满意。

你现在看的这个网站，就是例子。我把做视频的体会告诉 AI，它整理成案例、设计页面并更新到 GitHub。首页内容太长，我说“移到独立页面”；标题下面的横线太乱，我说“删掉”。这些想法很快就变成了能打开、能分享的网页。

一个人，也能持续维护自己的网站

我负责内容、审美和取舍，AI 承担编辑、排版、写代码和发布中的具体操作。不需要每次先找到文件、研究样式，再动手修改；我可以直接描述想要的结果，并检查实际页面。

  1. 说出要表达什么

    提供一段想法、一次经历或已有文章。比如：“把这周用 AI 做视频的过程，整理成第一个应用案例。”

  2. 让 AI 整理成网页

    确定标题、摘要、步骤和例子，设计适合手机与电脑阅读的页面。篇幅长的内容放独立页，首页只留入口。

  3. 放到 GitHub Pages

    将 HTML、CSS 和图片保存到 GitHub 仓库，通过 Pages 发布。这样的个人静态网站不需要自己维护一台网站服务器。

  4. 把域名入口接好

    有自己的域名时，可以让 AI 协助配置 AWS 上的解析与跳转，让访客从熟悉的网址进入网站。先明确入口和目标，再验证访问结果。

  5. 指着页面提出修改

    在 Codex 的内置浏览器里查看网页，点选要修改的标题、卡片或区域，再说清楚希望怎样改变。

  6. 检查，然后持续更新

    AI 修改源文件并发布，随后检查线上页面、链接与手机排版。新的想法继续加入，网站就成为不断积累的个人作品。

POINT & PROMPT · 指到哪里，说改哪里

“这个地方，帮我这样改。”

最直观的地方，是可以把反馈直接落在页面上。在内置浏览器里选择 Annotate（批注），点击一个元素或框选区域，写下修改要求，再让 Codex 根据批注处理。不同版本的入口名称和外观可能不同。

① 选中位置

点选标题，或框出那张占空间太多的卡片，让 AI 知道“这里”具体指什么。

② 说清结果

“把这里缩成一句摘要，加一个查看完整案例的链接，其他部分保持不变。”

点选解决的是“改哪里”的沟通问题。真正上线仍要修改网站源文件并重新发布；不是点一下任何网站，就能永久改变它。你需要拥有对应网站的编辑权限。

页面托管可以免费，域名费用另算

GitHub Pages：放网页

GitHub Free 的公开仓库支持 Pages，可免费托管这类静态页面。文章、个人介绍和案例展示都很适合。仓库公开意味着源码也会公开，不把账号密钥放进去。

GitHub Pages 官方说明 ↗

AWS：处理域名入口与跳转

AI 可以在授权范围内协助配置域名相关服务。DNS 解析和网页跳转是两件事：前者找到服务，后者把浏览器带到目标网址；可根据需求使用 Route 53、S3 跳转与 CloudFront 等服务。域名注册和 AWS 资源可能收费，不等于整套方案全免费。

AWS 网页跳转说明 ↗

这个案例介绍网站编辑的用法，不代表本次新增案例时重新配置了 AWS。具体域名方案应以实际账户配置为准；GitHub Pages 也可以直接绑定自定义域名，不一定需要 AWS。

我们刚刚做过的三个小修改

长案例 → 独立页面

“首页占用太多空间。”于是完整内容搬到独立页面，首页保留摘要和链接。

零散体会 → 清楚的文章

“竞争力还是人的竞争力。”于是整理出形象、表达和思想，并加入投资、旅游的例子。

视觉反馈 → 精确调整

“三个标题下面的长横线删掉。”一句具体反馈，就能定位并修改对应的页面样式。

网站不必等到所有内容都准备好才开始。
有一个想法，就让 AI 帮你把它整理、展示，再一点点改好。

可以直接试的指令
这是我的个人网站和 GitHub 仓库。请新增一个应用案例：主页只放标题、一句话摘要和链接，完整内容放独立页面，并沿用现有设计。 我会在内置浏览器里点选需要修改的地方并留下要求。请只修改相关部分，检查手机显示和链接，得到发布授权后更新网站并确认上线。
